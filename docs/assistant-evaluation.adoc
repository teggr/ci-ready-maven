== Procedure before enabling a production model

. Review provider data processing/retention terms and approve an operating budget.
. List models available to the account using the provider's authenticated API.
  Pick at least two viable small hosted models; record exact identifiers and
  date. Cloud CLI aliases are not necessarily direct API model identifiers.
. Run every case at least five times through the real retrieval/prompt/validator
  pipeline, after a separate warmup. Never disable validators to improve scores.
. Record accepted exact excerpts and source IDs, abstentions, errors/timeouts,
  provider usage metadata (input/output tokens where supported), and wall time.
  Store results outside the repository if they contain user/provider data.
. Verify every accepted response manually against the fixed index. Citation
  validity, unsupported claims and abstention correctness are separate measures.
  Structured output alone is not factual validation.
. Compute median and p95 latency including failed requests; report failures
  separately, rather than silently dropping them. Test provider unavailability,
  invalid credentials, timeout and exhausted usage limits.
. Calculate estimated cost per accepted answer using that day's published prices:
  `(inputTokens * inputPricePerMillion + outputTokens * outputPricePerMillion) / 1000000`.
  For subscriptions or quotas without per-token pricing, report the subscription,
  limits and amortization assumptions; do not invent a zero marginal-cost claim.
. Require no unsupported accepted claims/citations, correct configuration
  reproduction, and agreed latency/abstention targets. Choose on measured
  quality/cost/latency, not parameter count.
. Record the result below and approve the provider/model/domain before changing
  the disabled widget configuration. If no candidate meets the targets, remain off.

== Retrieval evaluation

Ordinary tests use mocked models, so ranking, relevance decisions and guardrails
are repeatable without a key. Evaluate recall for the expected IDs, precision of
the bounded candidate set, and abstention on missing facts separately from model
selection quality. A successful retrieval is not proof the requested fact exists.

The initial answer format intentionally quotes catalogue evidence rather than
allowing free-form factual prose. It can present multiple records for comparison
and exact existing examples, but it does not promise arbitrary Maven consulting.
Do not relax this contract to make an unanswerable test appear successful.

If recorded lexical misses demonstrate inadequate recall, first adjust documented
aliases/weights and test the same set. Consider semantic retrieval only with
measured evidence; it must retain the same relevance, bounded-context, citation
and exact-evidence checks.
